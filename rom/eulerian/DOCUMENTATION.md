# FLOWUnsteady / VarFlExI Dataset Export Interface and Eulerian Utilities

## Architectural Overview

**Key Architectural Decision:**
VarFlExI simulations and Eulerian fluid-field evaluations occur upstream in the simulation environment. FLOWUnsteady natively evaluates velocity and vorticity at Cartesian grid nodes via:

```julia
uns.computefluiddomain(pfield, grids)
```
(Reference: [FLOWUnsteady Fluid Domain API](https://flow.byu.edu/FLOWUnsteady/api/flowunsteady-postprocessing-fdom/) and [Rotor-Hover Fluid Domain Example](https://flow.byu.edu/FLOWUnsteady/examples/rotorhover-fdom/)).

This repository (`control-aware-roms-for-lagrangian-methods`) strictly acts as a downstream **Reduced-Order Model (ROM) training, inference, and evaluation pipeline**. It:
- **Never** re-implements Biot-Savart particle-to-grid evaluation.
- **Never** requires FLOWUnsteady or Julia runtime during ROM training or inference.
- Consumes independently exported HDF5 datasets containing Eulerian snapshots and aeroelastic states.
- Retains generic grid definition, fluid masking, and curl-based vorticity recovery utilities.

## Native FLOWUnsteady / VarFlExI Export Interface

VarFlExI simulations export HDF5 datasets conforming to the following structure. Single or multiple trajectories are supported.

### HDF5 Schema Specification

```
/metadata/
    time                            (K,) float64       Physical time timestamps [s]
    coords_x                        (Nx,) float64      1D x-grid coordinates [m]
    coords_y                        (Ny,) float64      1D y-grid coordinates [m]
    coords_z                        (Nz,) float64      1D z-grid coordinates [m]
    fluid_mask                      (Nx, Ny, Nz) bool  [Optional] True=fluid, False=solid
    @axis_order                     string             Permutation of 'xyz' (default: "xyz")
    @bounds_x, bounds_y, bounds_z   (2,) float64       Spatial bounding boxes
    @resolution_x, resolution_y, ... (int)             Grid points along each axis
    @units                          string             Spatial units (default: "m")
    @has_fluid_mask                 bool               Whether fluid_mask is present

/snapshots/
    velocity                        (K, Nx, Ny, Nz, 3) float64  Cartesian velocity (ux, uy, uz) [m/s]
    vorticity                       (K, Nx, Ny, Nz, 3) float64  [Optional] Vorticity (wx, wy, wz) [1/s]

/structural/                                           [Optional: Aeroelastic / VarFlExI data]
    displacement                    (K, ...) float64   Structural node displacements [m]
    velocity                        (K, ...) float64   Structural velocities [m/s]
    acceleration                    (K, ...) float64   Structural accelerations [m/s^2]
    aerodynamic_forces              (K, ...) float64   Integrated or distributed aero forces [N]

/parameters/                                           [Optional: Simulation parameters]
    @reynolds_number                float64
    @inflow_velocity                float64
    @rpm                            float64
```

### Multi-Trajectory Support
When multiple independent simulation runs are stored within a single HDF5 container, each trajectory is structured under its own group:
```
/trajectory_001/metadata/...
/trajectory_001/snapshots/...
/trajectory_002/metadata/...
...
```
Alternatively, multiple trajectories can be provided as a directory of individual `.h5` files.

## Retained Eulerian Utilities

The following modules in `rom.eulerian` provide standalone post-processing support:

1. **`EulerianGrid` (`rom/eulerian/grid.py`)**:
   - Represents the deterministic 3D spatial discretisation.
   - Provides coordinate arrays, spacings, flat point orderings, and HDF5 round-trip serialization.

2. **`FluidMask` (`rom/eulerian/masking.py`)**:
   - Represents boolean fluid/solid masks for immersed bodies (rotor blades, nacelles, fuselages).
   - Identifies active fluid cells for state encoding in POD and sets solid regions to `NaN` in decoded fields.

3. **`compute_vorticity` (`rom/eulerian/vorticity.py`)**:
   - Evaluates $\boldsymbol{\omega} = \nabla \times \mathbf{u}$ using 2nd- or 4th-order finite difference stencils.
   - Used for **vorticity recovery** from decoded velocity predictions generated by velocity-only ROMs.
